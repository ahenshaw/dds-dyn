# Building eProsima's Fast DDS Python bindings (Linux and Windows)

This guide builds [Fast-DDS-python](https://github.com/eProsima/Fast-DDS-python), eProsima's
SWIG bindings for Fast DDS. It uses plain CMake, so you don't need colcon or vcstool. It also
builds a Python type module from your IDL with `fastddsgen -python`.

> **Status of these instructions**
> - **Linux** has been tested end to end. These exact steps (Ubuntu 24.04, Python 3.12, in Docker)
>   produced a working Fast-DDS-python node. It exchanged data with Fast DDS C++, the HDDS
>   Rust crate and the HDDS Python SDK, and every direction received 10/10 samples.
> - **Windows** has *not* been tested end to end. The Fast DDS part uses the same CMake options
>   that build Fast DDS 3.6.2 on the GitHub Actions `windows-latest` runner for the `fastdds-dyn`
>   wheel. The SWIG and Python steps follow from those and from how Python loads DLLs on Windows.
>   Expect to adjust paths.

**If you don't need eProsima's own API, try `fastdds-dyn` (this repo, see the [README](../README.md)) first.**
It is a pip-installable wheel for Linux and Windows with Fast DDS 3.6.2 linked in statically.
It loads IDL at runtime and you pass samples as dicts. You don't need a compiler, SWIG, Java,
or fastddsgen. The rest of this guide is for when you need the full `fastdds` SWIG API, or
generated classes.

---

## 1. What gets built, and why versions matter

Five pieces are involved. **Their versions must all match.** Most "it built but won't import"
and "symbol not found" errors come from a Fast-DDS-python release built against a different
Fast DDS. Each Fast-DDS-python release lists its matching versions in `fastdds_python.repos`.

| Component | Version | What it is |
|---|---|---|
| foonathan_memory_vendor | v1.4.1 | Memory allocator used by Fast DDS |
| Fast-CDR | v2.3.6 | Serialization library |
| Fast-DDS | v3.6.2 | The DDS implementation (`libfastdds`) |
| Fast-DDS-python | v2.6.2 | SWIG bindings → `import fastdds` |
| Fast-DDS-Gen | v4.3.0 | IDL code generator (Java); `-python` emits the type module |

These versions are the set Fast-DDS-python v2.6.2 pins. If you want a different Fast DDS
version, open `fastdds_python.repos` in the matching Fast-DDS-python tag and use the versions
listed there.

You end up with two Python modules:

1. **`fastdds`**: the generic API (DomainParticipant, Publisher, DataWriter, QoS, …).
2. **A type module per IDL file**, e.g. `sensors.Sensor` with `Reading` and
   `ReadingPubSubType`. This is a SWIG extension too, generated by
   `fastddsgen -python` and compiled against the same Fast DDS.

## 2. Linux (tested on Ubuntu 24.04)

### 2.1 Prerequisites

```bash
sudo apt-get update
sudo apt-get install -y build-essential cmake git ca-certificates \
    libasio-dev libtinyxml2-dev libssl-dev \
    openjdk-17-jdk-headless \
    python3 python3-dev swig4.1
```

- `python3-dev` provides the headers and libpython that SWIG's CMake needs.
- SWIG 4.1 works. Very old SWIG 3.x does not handle Fast DDS 3 headers.
- Java (JDK 11 or newer) is needed only for Fast-DDS-Gen.

On other distributions, install the equivalent packages. If your distribution has no Asio or
TinyXML2 package, see the `THIRDPARTY_*` options in the Windows section; they work on Linux too.

### 2.2 Build the C++ libraries

Everything below installs to `/usr/local`. To avoid `sudo`, use a prefix such as
`$HOME/fastdds` instead (see 2.6).

```bash
mkdir -p ~/fastdds-src && cd ~/fastdds-src
J=$(nproc)

git clone --depth 1 -b v1.4.1 https://github.com/eProsima/foonathan_memory_vendor.git
cmake -S foonathan_memory_vendor -B build/foonathan -DBUILD_SHARED_LIBS=ON -DCMAKE_BUILD_TYPE=Release
sudo cmake --build build/foonathan --target install -j$J

git clone --depth 1 -b v2.3.6 https://github.com/eProsima/Fast-CDR.git
cmake -S Fast-CDR -B build/fastcdr -DCMAKE_BUILD_TYPE=Release
sudo cmake --build build/fastcdr --target install -j$J

git clone --depth 1 -b v3.6.2 https://github.com/eProsima/Fast-DDS.git
cmake -S Fast-DDS -B build/fastdds -DCMAKE_BUILD_TYPE=Release -DCOMPILE_EXAMPLES=OFF -DCOMPILE_TOOLS=ON
sudo cmake --build build/fastdds --target install -j$J

sudo ldconfig
```

The Fast DDS build is the slow step, about 5–15 minutes depending on the machine.

### 2.3 Build Fast-DDS-Gen (the IDL generator)

```bash
git clone --depth 1 -b v4.3.0 --recursive https://github.com/eProsima/Fast-DDS-Gen.git
cd Fast-DDS-Gen
./gradlew assemble
sudo ./gradlew install --install_path=/usr/local
cd ..
fastddsgen -version        # should print 4.3.0
```

`--recursive` is required, because the IDL grammar is in a git submodule.

### 2.4 Build the `fastdds` Python module

```bash
git clone --depth 1 -b v2.6.2 https://github.com/eProsima/Fast-DDS-python.git
cmake -S Fast-DDS-python/fastdds_python -B build/fastdds_python -DCMAKE_BUILD_TYPE=Release
sudo cmake --build build/fastdds_python --target install -j$J
```

The build compiles one very large SWIG wrapper file. It needs several GB of RAM per compile
job, so if the build gets killed for running out of memory, rerun it with `-j2` or `-j1`.

### 2.5 Generate and build the type module for your IDL

```bash
mkdir -p ~/myapp/gen && cd ~/myapp
fastddsgen -python -d gen -replace idl/Sensor.idl
cmake -S gen -B build -DCMAKE_BUILD_TYPE=Release
sudo cmake --build build --target install -j$J
sudo ldconfig
```

`gen/` will contain the C++ type support, a SWIG `.i` file and a `CMakeLists.txt`.
`gen/` must contain only the output from this run, so rerun the command with `-replace`
whenever the IDL changes.

### 2.6 Make Python find the modules

On Ubuntu and Debian this is the step that usually fails: **neither module lands on Python's
default `sys.path`.**

- `fastdds` goes to `<prefix>/lib/python3.X/site-packages`.
- The generated type module goes to Debian's `posix_local` scheme, which for prefix
  `/usr/local` is `/usr/local/local/lib/python3.X/dist-packages` (yes, `local/local`).

Find them and add both to `PYTHONPATH`:

```bash
find /usr/local -name 'fastdds.py' -o -name '_fastdds_python*.so'
find /usr/local -path '*sensors*' -name '*.py'

export PYTHONPATH=/usr/local/lib/python3.12/site-packages:/usr/local/local/lib/python3.12/dist-packages
```

If you used a non-system prefix such as `$HOME/fastdds`:

```bash
# when configuring each project (2.2, 2.4, 2.5):
#   -DCMAKE_INSTALL_PREFIX=$HOME/fastdds -DCMAKE_PREFIX_PATH=$HOME/fastdds
# and drop the sudo on the install steps
export LD_LIBRARY_PATH=$HOME/fastdds/lib:$LD_LIBRARY_PATH
export PATH=$HOME/fastdds/bin:$PATH
export PYTHONPATH=...the two directories found with find...
```

### 2.7 Smoke test

```bash
python3 -c "import fastdds; print('fastdds OK')"
python3 -c "from sensors.Sensor import Reading, ReadingPubSubType; print('type module OK')"
```

Section 4 has a minimal publisher.

## 3. Windows (untested end to end, see the status note at the top)

### 3.1 Prerequisites

- **Visual Studio 2022** with the *Desktop development with C++* workload. Run every command
  below in an **"x64 Native Tools Command Prompt for VS 2022"**.
- **CMake** 3.20 or newer, and **Git**.
- **Python 3.x (64-bit)** from python.org. Its installer includes `libs\python3X.lib`, which
  the build needs. Microsoft Store Python and 32-bit Python won't work.
- **SWIG 4.x**: download `swigwin-4.x` from swig.org, unzip it (e.g. to `C:\swigwin`) and add
  that directory to `PATH`, or pass `-DSWIG_EXECUTABLE=C:\swigwin\swig.exe`.
- **JDK 11 or newer** (e.g. Temurin 17) for Fast-DDS-Gen, with `JAVA_HOME` set.

Fast DDS's build tree is very deep, so **use short paths** to stay under Windows' 260-character
limit: a short source directory such as `C:\fdw` and a short install prefix such as `C:\fdd`.
Enabling long paths (`git config --system core.longpaths true` plus the registry setting) also
helps, but MSBuild can still fail with long paths.

### 3.2 Build the C++ libraries

On Windows, Visual Studio generators build several configurations, so pass `--config Release`
when building. This also sets the install prefix and avoids needing OpenSSL, Asio or TinyXML2
on the system:

```bat
mkdir C:\fdw && cd /d C:\fdw
set P=C:\fdd

git clone --depth 1 -b v1.4.1 https://github.com/eProsima/foonathan_memory_vendor.git
cmake -S foonathan_memory_vendor -B b\foonathan -DCMAKE_INSTALL_PREFIX=%P% -DBUILD_SHARED_LIBS=ON
cmake --build b\foonathan --config Release --target install

git clone --depth 1 -b v2.3.6 https://github.com/eProsima/Fast-CDR.git
cmake -S Fast-CDR -B b\fastcdr -DCMAKE_INSTALL_PREFIX=%P%
cmake --build b\fastcdr --config Release --target install

git clone --depth 1 -b v3.6.2 https://github.com/eProsima/Fast-DDS.git
cmake -S Fast-DDS -B b\fastdds -DCMAKE_INSTALL_PREFIX=%P% -DCMAKE_PREFIX_PATH=%P% ^
      -DTHIRDPARTY_Asio=FORCE -DTHIRDPARTY_TinyXML2=FORCE ^
      -DNO_TLS=ON -DSECURITY=OFF -DCOMPILE_EXAMPLES=OFF -DCOMPILE_TOOLS=ON
cmake --build b\fastdds --config Release --target install
```

- `THIRDPARTY_Asio/TinyXML2=FORCE` use the copies bundled in Fast DDS's git submodules.
  `--depth 1` clones still fetch them; if not, run `git submodule update --init` in `Fast-DDS`.
- `NO_TLS=ON -DSECURITY=OFF` remove the OpenSSL dependency. Leave them out if you need TLS or
  DDS Security, and install OpenSSL (e.g. via vcpkg) instead.

### 3.3 Build Fast-DDS-Gen

```bat
cd /d C:\fdw
git clone --depth 1 -b v4.3.0 --recursive https://github.com/eProsima/Fast-DDS-Gen.git
cd Fast-DDS-Gen
gradlew.bat assemble
gradlew.bat install --install_path=C:\fdd
C:\fdd\bin\fastddsgen.bat -version
```

### 3.4 Build the `fastdds` Python module

```bat
cd /d C:\fdw
git clone --depth 1 -b v2.6.2 https://github.com/eProsima/Fast-DDS-python.git
cmake -S Fast-DDS-python\fastdds_python -B b\fastdds_python ^
      -DCMAKE_INSTALL_PREFIX=%P% -DCMAKE_PREFIX_PATH=%P% ^
      -DPython3_EXECUTABLE=C:\Path\To\python.exe
cmake --build b\fastdds_python --config Release --target install
```

- If more than one Python is installed, set `Python3_EXECUTABLE` to the one you will run.
  The module only loads in that exact Python version.
- **Debug vs Release.** A Debug build links against `python3X_d.lib`, which only exists if you
  installed Python's debug binaries. Stick to `--config Release`.

### 3.5 Generate and build the type module

```bat
cd /d C:\myapp
C:\fdd\bin\fastddsgen.bat -python -d gen -replace idl\Sensor.idl
cmake -S gen -B build -DCMAKE_INSTALL_PREFIX=%P% -DCMAKE_PREFIX_PATH=%P% ^
      -DPython3_EXECUTABLE=C:\Path\To\python.exe
cmake --build build --config Release --target install
```

### 3.6 Make Python find the modules **and their DLLs**

This is the step most likely to go wrong on Windows. Since Python 3.8, **`PATH` is no longer
searched for an extension module's DLL dependencies.** If `fastdds.dll`, `fastcdr.dll` or
`foonathan_memory*.dll` can't be found, the import fails with
`ImportError: DLL load failed while importing _fastdds_python: The specified module could not be found.`

1. Find where the modules were installed:
   ```bat
   dir /s /b C:\fdd\fastdds.py C:\fdd\_fastdds_python*.pyd
   dir /s /b C:\fdd\*Sensor*.pyd
   ```
2. Add those directories to `PYTHONPATH`.
3. Register the DLL directory **before** importing:
   ```python
   import os
   os.add_dll_directory(r"C:\fdd\bin")   # where fastdds-3.6.dll, fastcdr-2.3.dll, ... live
   import fastdds
   from sensors.Sensor import Reading, ReadingPubSubType
   ```
   Or copy the DLLs from `C:\fdd\bin` next to the `.pyd` files.

If the error persists, a dependency is still missing. Open the `.pyd` with
[Dependencies](https://github.com/lucasg/Dependencies) to see which DLL it can't find.

## 4. Minimal publisher (both platforms)

```python
import fastdds
from sensors.Sensor import Reading, ReadingPubSubType

factory = fastdds.DomainParticipantFactory.get_instance()
pqos = fastdds.DomainParticipantQos()
factory.get_default_participant_qos(pqos)
participant = factory.create_participant(0, pqos)

ts = fastdds.TypeSupport(ReadingPubSubType())
ts.register_type(participant)
topic_qos = fastdds.TopicQos()
participant.get_default_topic_qos(topic_qos)
topic = participant.create_topic("SensorReadings", ts.get_type_name(), topic_qos)

pub_qos = fastdds.PublisherQos()
participant.get_default_publisher_qos(pub_qos)
publisher = participant.create_publisher(pub_qos)

wqos = fastdds.DataWriterQos()
publisher.get_default_datawriter_qos(wqos)      # on the Publisher, not the participant
writer = publisher.create_datawriter(topic, wqos)

r = Reading()
r.node_id(4); r.node_name("py"); r.seq(1); r.value(1.5); r.text("hello")
writer.write(r)
```

A full publisher/subscriber also needs a reader. Give it a `fastdds.DataReaderListener`
subclass whose `on_data_available` calls `reader.take_next_sample(sample, fastdds.SampleInfo())`
in a loop until it no longer returns `fastdds.RETCODE_OK`.

## 5. Gotchas when using the bindings

- **Default-QoS getters live on the parent entity.** Call `get_default_datawriter_qos` on the
  `Publisher` and `get_default_datareader_qos` on the `Subscriber`, not on the participant.
- **Bounded strings aren't Python `str`.** A `string<32>` member returns a `fixed_string_32`
  proxy object. Call `.to_string()` on it. Unbounded `string` members return `str`.
- **Fields are accessor methods**: `r.seq()` reads the field and `r.seq(5)` sets it.
- **Listeners are SWIG directors.** Subclass `fastdds.DataReaderListener`, call
  `super().__init__()`, and **keep a Python reference** to the listener for as long as the
  reader exists. If the listener is garbage-collected, callbacks stop or the process crashes.
  Callbacks run on a Fast DDS thread.
- **Rebuild the type module whenever you change the IDL or Fast DDS.** It contains compiled
  C++ type support and only works with the exact Fast DDS build it was compiled against.
- **Two Fast DDS processes on one host will use shared memory**, and that fails if one of them
  is in a container with a private IPC namespace or runs as a different user. Set
  `FASTDDS_BUILTIN_TRANSPORTS=UDPv4` on one side. In testing, discovery still matched every
  endpoint but no data arrived, which makes this hard to spot.
- **Talking to other DDS vendors:** Fast DDS 3 readers accept only XCDR1 by default. To
  receive from an XCDR2-only writer, set the reader QoS `representation().m_value` to
  `[XCDR2, XCDR]`. Otherwise the endpoints report incompatible QoS and no data flows.

## 6. Troubleshooting

| Symptom | Likely cause / fix |
|---|---|
| `ModuleNotFoundError: No module named 'fastdds'` | Install directory not on `sys.path`. See 2.6 or 3.6. |
| `ImportError: libfastdds.so.3.6: cannot open shared object file` | Run `sudo ldconfig`, or add `<prefix>/lib` to `LD_LIBRARY_PATH`. |
| `ImportError: DLL load failed while importing _fastdds_python` | Call `os.add_dll_directory(r"C:\fdd\bin")` before importing. See 3.6. |
| `undefined symbol: _ZN8eprosima...` on import | Fast DDS and Fast-DDS-python versions don't match, or there are two Fast DDS installs (e.g. ROS 2's in `/opt/ros`). Check `ldd` on the `.so`. |
| CMake: `Could NOT find fastdds` / `fastcdr` | Pass `-DCMAKE_PREFIX_PATH=<prefix>`. |
| CMake: `Could NOT find SWIG` | Install SWIG 4.x, or pass `-DSWIG_EXECUTABLE=...`. |
| CMake: `Could NOT find Python3 (missing: Development)` | Install `python3-dev` (Linux) or python.org Python with its `libs` folder (Windows). |
| Compiler killed during the Fast-DDS-python build | Out of memory compiling the SWIG wrapper. Use `-j1` or `-j2`. |
| MSBuild: path too long or file not found deep in the build tree | Use shorter source/build directories (`C:\fdw`, `b\...`). |
| `fastddsgen` fails with a grammar or ANTLR error | The Fast-DDS-Gen clone is missing its submodule. Re-clone with `--recursive`. |
| Endpoints match but no data arrives between two Fast DDS processes | Shared-memory transport. Set `FASTDDS_BUILTIN_TRANSPORTS=UDPv4`. |
